## 1. Background

desnotch is a macOS menu-bar app (SwiftPM, macOS 13+, library target `DesnotchCore`) with a notch pill UI. We are adding
**voice control**, OFF by default. The user holds a hotkey, speaks, and either a fixed local command runs (volume, media, open
an app, timer) or, if enabled, the request goes to the user's local **Hermes** agent (a Python agent; a cloud model sits behind
it). The design (read it): `docs/voice/PLAN.md`. The contracts: `Sources/DesnotchCore/Voice/Contracts/{VoiceTypes,Protocols,VoiceSessionModel,VoiceStubs}.swift`.
The merged work packages gave you:

- UI: `VoiceSectionView`, wings, status-menu items, Settings section, `VoiceCuePlayer`. They only talk to `VoiceSessionModel`.

**Your job has three parts, in this order, each its own invocation with its own gate (your invocation names which one):**

- **Part A: the coordinator and app wiring.** The `@MainActor` object that owns the reducer's `VoiceContext`, feeds it events (keys, speech, timers, lock, UI actions, agent), interprets its effects with the real platform objects, and publishes the result to `VoiceSessionModel`. ## 2. Non-negotiable safety properties (they decide every judgement call)

1. **desnotch never creates, edits, or touches anything in `~/.hermes`.** The profile named `voice` is created and locked by the human (`chflags uchg` on its `config.yaml`). Our code only READS it at runtime for the preflight and refuses the Hermes lane until it checks out.
2. **You (the implementer) must never run `hermes`** (not even `--version`), never read `~/.hermes/config.yaml`, `~/.hermes/profiles/**/config.yaml`, `.env`, `auth.json`, or any secret. You MAY read the Hermes Python SOURCE under `~/.hermes/hermes-agent/` (read-only) to learn the ACP shapes and config key names. All your tests use synthetic fixtures and a scripted fake transport.
3. **Nothing is ever approved by voice.** Approvals are visual, bound to a random nonce, and answered `once` or `deny` only; never `session`/`always`.
4. **Default-deny toolset + tripwire.** The reducer already trips on any tool that is not explicitly allowed (R83). You make sure `AgentEvent.toolActivity` is emitted exactly once per tool call, at its START event: Hermes sends a single `tool_call` update (no `status`, the name only in the title prefix) when a tool starts, so the start event itself is the signal (B.5). A mapper that waits for an `in_progress` update would never fire and every tool would run unnoticed.
5. **The stop is total.** Hard stop = interrupt, wait, `killpg(SIGTERM)`, wait, `killpg(SIGKILL)` on the agent's OWN process group, and report survivors. Never `hermes pause`, never `hermes serve --stop`, never `pkill`/`killall hermes`, never touch a process desnotch did not spawn.
6. **Fail closed.** No preflight pass = no Hermes lane. Audit unwritable = no risky actions (section 4.4). Unknown lock state = locked.
7. **No pentest/engagement context on the voice path.** Nothing from Interseptor, vault, engagements, Notion or memory MCPs is ever added to a prompt, and the `mcp_servers` list passed to ACP is always empty.
8. **Privacy.** Transcripts, replies and command text are live content: no logs, no prints, never in the audit log (hashes/codes only).

### A.1 API

```swift
@MainActor
final class VoiceCoordinator {
    init(
        model: VoiceSessionModel, settings: SettingsStore, clock: VoiceClock,
        recognizer: SpeechRecognizing, synthesizer: SpeechSynthesizing, executor: LocalExecuting,
        backend: AgentBackend,                                      // ONE instance, owned by AppComposition (see "Backend identity")
        terminateAgentNow: @escaping @Sendable () -> Void = {},     // synchronous last-resort kill, wired in Part B
        audit: AuditLogging, makeKeys: @escaping @MainActor (VoiceHotkeyChoice) -> PushToTalkSource,
        lock: LockStateProviding, ducker: MediaDucking,
        permissions: VoicePermissionProviding, cues: VoiceCuePlaying,
        timers: VoiceTimerScheduling,                               // REQUIRED, NO default (compile trap, below)
        dailyTurns: DailyTurnCounter, isPrivacyMode: @escaping @MainActor () -> Bool,
        makeNonce: @escaping () -> String = { UUID().uuidString }, debugTypingEnabled: Bool
    )
    func start()                      // idempotent; applies the current settings once, then observes them. Does nothing visible unless voiceEnabled.
    func stop()                       // app termination or disable: cancel everything, release hotkeys, restore volume, kill the agent (see below)
    func dispatch(_ event: VoiceEvent)  // internal entry; tests call it directly
    func submitTyped(_ text: String)  // debug only
    private(set) var context: VoiceContext
}
```

**Compile trap: no default argument may call a `@MainActor` initializer.** `RunLoopTimerScheduler` conforms to the `@MainActor` protocol `VoiceTimerScheduling`, so it is main-actor isolated and `timers: VoiceTimerScheduling = RunLoopTimerScheduler()` does not compile ("call to main actor-isolated initializer 'init()' in a synchronous nonisolated context"; reproduced with swiftc 6.1 in Swift 5 mode, and CI's Swift 5.10 rejects it too). Therefore `timers` has NO default: `AppComposition` (itself `@MainActor`) passes `timers: RunLoopTimerScheduler()` explicitly (A.8) and every test passes `CoordManualTimerScheduler()`. The defaults that remain are fine and stay: `terminateAgentNow` and `makeNonce` are closure literals; a `@MainActor () -> T` closure literal is fine too; `HermesAgentBackend` and `HermesProcessGuard` defaults (Part B) are not main-actor types. The same trap is documented for `VolumeDucker` in the constructor table of `docs/voice/WP-PLATFORM.md` section 3. Do not "fix" it with `nonisolated init()` on the scheduler or by dropping `@MainActor` from the protocol.

**Backend identity (read this twice).** `AppComposition` owns exactly ONE backend object for the app's lifetime and passes that SAME instance to the coordinator: in Part A it is `NullBackend()`; in Part B it is a lazily created stored `HermesAgentBackend` (constructing it spawns nothing). There is **no backend factory**. `submit`, `respond`, `cancelTurn`, `emergencyStop`, `preflight` and `shutdown` always go to that one instance, so a hard stop always reaches the object that owns the child process, and turning the lane off cannot strand a running child. The `voiceHermesLane` setting is NOT a backend switch: it gates `env.hermesLaneReady` (A.2) and the lane check (A.5).
`AgentBackend.shutdown()` is async, but app termination calls `stop()` synchronously and an unawaited `Task` does not run before the process exits, which would orphan `hermes acp`. So `stop()` calls `terminateAgentNow()` directly, a synchronous closure that `AppComposition` wires (Part B) to `HermesAgentBackend.terminateNow()` (B.6); Part A leaves the default `{}`. `AppComposition.stopOwnedResources()` calls `voiceCoordinator?.stop()`. **`stop()` semantics (exact, and idempotent):** it does NOT go through the reducer (no `.featureDisabled` dispatch, no async work: the process is about to exit). It cancels every stored timer handle, `keyTask`, `lockTask`, the lane-check task and the didBecomeActive observer, stops the keys, calls `recognizer.cancel()` and `synthesizer.stop()`, calls `ducker.restore()` and `terminateAgentNow()`, and skips the audit chain and every `await`. A second call (the SIGTERM handler and `applicationWillTerminate` can both reach it) is a no-op: it must not crash, must not call `terminateAgentNow()` or `keys.stop()` again, and the backend sees a single `terminateNow`. `testStopTwiceIsIdempotent` pins this.

`VoiceTimerScheduling` and its handle (in `VoiceTimers.swift`), exact:

```swift
@MainActor protocol VoiceTimerHandle: AnyObject { func cancel() }
@MainActor protocol VoiceTimerScheduling { func schedule(after seconds: Double, _ action: @escaping @MainActor () -> Void) -> VoiceTimerHandle }
```

Real: `RunLoopTimerScheduler` is **un-keyed**: every `schedule(after:_:)` makes one independent non-repeating `Timer` on `.common` mode (like `FocusTimerController`'s scheduler) and `handle.cancel()` invalidates that timer. It knows nothing about `(kind, generation)`. **Keying and replacement live only in the coordinator** (A.3, `.startTimer` row); the protocol above is exact and has no key parameter. **Timer semantics the reducer relies on:** a `.startTimer(kind, generation:, seconds:)` REPLACES any pending timer with the same `(kind, generation)`. This matters for a second agent approval card in one turn: R85 starts a 60 s `.approval` timer under the same generation as the first card's, so the first card's timer is cancelled and the second card gets its full 60 s (without replacement the first timer would expire the second card early). R32's second `.listenCap` replaces the first the same way. **The real scheduler's closure is not main-actor isolated:** Foundation's `Timer` block is `@Sendable` and non-isolated on Swift 5.10, so `RunLoopTimerScheduler` calls the `@MainActor` action as `MainActor.assumeIsolated { action() }` inside the timer block (the local 6.1 compiler accepts a bare call, CI's 5.10 does not). `VoiceTimersTests` defines the test double `CoordManualTimerScheduler` and uses it; the coordinator tests reuse it. Its minimum surface (the tests rely on exactly this; the double never learns `(kind, generation)`, only the coordinator keys handles): `private(set) var scheduled: [Double]` (the `seconds` of every `schedule` call, in order), `private(set) var cancelledCount: Int`, `var pendingCount: Int` (scheduled, not yet fired, not cancelled), `func fire(index: Int)` (runs the action scheduled at that position unless it was cancelled or already fired), `func fireLatest()` (the newest non-cancelled pending one), and `func fireAll()`. A test that needs "the review timer of generation 1" fires by position (the review timer is the one whose `seconds == 1.5`: `fire(index: scheduled.lastIndex(of: 1.5)!)` is fine in test code), and a stale-timer test dispatches `.timerElapsed(kind, generation: old)` straight into `coordinator.dispatch`, which is exactly what an elapsed timer does. `VoiceTimersTests` also tests the REAL scheduler with 10 ms timers, written as SYNC tests (`wait(for:timeout:)`; the stub also offers `await fulfillment(of:timeout:)`, which a test may use if it is `async`, because real XCTest warns about `wait` called directly from an async test): a timer fires exactly once (wait with an `expectation`, then `drainMainQueue()` twice and assert the counter is 1); a cancelled timer never fires (schedule it, cancel it, then schedule a 30 ms sentinel timer that fulfils an expectation; when the sentinel has fired the cancelled counter is still 0); `cancel()` twice is harmless.

### A.2 The dispatch loop

`dispatch(event)`: build `VoiceReducerEnv` (below), `let t = VoiceReducer.reduce(context, event, env: env)`, `context = t.context`, **run the effects in order**, then publish: `model.apply(context, reviewDeadline: context.state == .review ? reviewDeadline : nil)`; arm/disarm the Esc key (`keys.setCancelKeyArmed(armed)` where **`armed = context.state != .idle && context.state != .paused`** (Esc does something only in those states: `cancelRequested` is a no-op in `paused` (R132) and in `idle` (R14), and a global key that does nothing must not be stolen from other apps), only when the value changes). Re-entrancy: effects may synchronously cause more events (e.g. a fake executor); queue events and drain them in order instead of recursing (a simple `pending: [VoiceEvent]` + `isDispatching` flag). After each dispatch also run the timer clean-up of A.3.

`VoiceReducerEnv` per call: `now: clock.now()`, `voiceEnabled: voiceEnabledState`, `screenLocked: <see below>`, `hermesLaneReady: laneEnabled && model.hermesLaneStatus == .ready && model.hotkeyStatus == .active` (the cloud lane never runs while the global Stop chord is not registered: `CarbonPushToTalk.start()` returns `.unavailable` when it could not register the chord, yet the status-menu Talk path still works then; PLAN deviation 9), `hermesTurnsRemainingToday: dailyTurns.remaining(now: clock.now())`, `speechAllowed: settings.voiceTTSEnabled && !isPrivacyMode()`, `secondFactorAvailable: false`, `freshNonce: makeNonce()`. **`screenLocked` is read lazily** (`lock.isLocked` recomputes `CGSessionCopyCurrentDictionary()` plus an `NSWorkspace.runningApplications` scan on every call, so it must not run for every partial transcript). The reducer consults `env.screenLocked` only for `.talkPressed`, `.toggleTalk`, `.finalTranscript` (HANDLE_FINAL step 3, R51) and `.approveRequested` (R70/R78); define `static func consultsLock(_ event: VoiceEvent) -> Bool` returning true for exactly those four cases. For those events read `lock.isLocked` fresh and store it in `lastScreenLocked`; for every other event pass `lastScreenLocked` (initial value `true`, fail closed; it is irrelevant to the rules that do not consult it). `testLockIsReadOnlyForTheEventsThatConsultIt` pins this with `CoordFakeLock.isLockedReadCount`.
`voiceEnabledState` and `laneEnabled` are the coordinator's own mirrors of the two settings, updated ONLY from the values the Combine sinks emit (A.5), never by re-reading the setting. `dailyTurns` is stored as a `var` (its `increment(now:)` is mutating).

### A.4 Audit gate

`auditWritable` starts true. When it is false: an `.execute` effect for an intent whose tier is `>= .t2`, and every `.submitToAgent`, is NOT run; instead dispatch `.localExecutionFinished(.failure(.executionFailed("audit_unwritable")), generation: g)` or `.agent(.failed(.executionFailed("audit_unwritable")), generation: g)`. T0 local commands keep working. (Tier from `ConfirmationPolicy.tier(of:)`.) **Agent approvals are gated too** (safety rule 6: audit unwritable = no risky actions): when `auditWritable == false`, a `.respondToApproval(nonce, allow: true)` is sent to the backend as `allow: false`. Nothing else changes: the reducer has already moved on (R74 went to `acting`), and the agent finishes or fails by itself. `FileAuditLogger` default directory/instance is created in `AppComposition`.

**Accepted one-record lag.** `auditWritable` is updated after the asynchronous append of the PREVIOUS record, so the gate can lag by one record. That is accepted on purpose: the `route` record and the `approval requested` record of the same flow were appended at least 1.5 s (review window) or a card display earlier, so a failing disk is seen before the next risky action in practice. (The alternative, which a stricter implementation may choose, is to make the T2 `.execute` Task and the approval response await the tail of the ordered audit chain before running.)

### A.5 Inputs

- **Hotkey source: one per enable.** `keys` is created in `startVoice()` and nowhere else: `keys = makeKeys(hotkeyChoice)`, where `hotkeyChoice` is the coordinator's mirror of `settings.voiceHotkey` (updated only from the values its sink emits, like the other mirrors below). It is ALWAYS a fresh instance: a `CarbonPushToTalk` is single-use (`start()` after `stop()` returns `.unavailable` and registers nothing), so reusing the previous instance after Settings off, then on, with the same hotkey would leave the hotkeys dead and the status "unavailable". Then `let status = keys.start()` and ALWAYS `model.setHotkeyStatus(status)` (`.unavailable` means another app owns the combination, or the Stop chord ⌥⌘. could not be registered; Settings shows it). `keys.events` is consumed by one `keyTask` (a `Task { @MainActor [weak self] in ... }` started after `keys.start()`; cancelled and restarted on every enable and every hotkey change): `.pressed` => `.talkPressed`; `.released(h)` => `.talkReleased(heldSeconds: h)`; `.cancelKey` => `.cancelRequested`; `.stopKey` => `.stopAllRequested`.
- **Lock gate.** `lock.changes` is a computed property that returns a NEW stream on every access (WP-PLATFORM 3.4). Access it ONCE per enable, in `startVoice()`, and iterate it in one `lockTask`; the monitor installs its observers when that stream is created and removes them (and resets its flags) when the last stream terminates, which happens when `lockTask` is cancelled on disable. Do not access `changes` anywhere else and do not hold a stream while voice is off. `lock.isLocked` (read lazily for `env.screenLocked`, A.2) is recomputed from the system on every call and needs no stream to be correct. A change to `true` => `.screenLocked`.
- `NSApplication.didBecomeActiveNotification` (observed only while voice is enabled) -> `model.setPermissions(permissions.status())`, so Settings notices a grant made in System Settings. **The same handler also re-runs the lane check** when `laneEnabled && voiceEnabledState` and `model.hermesLaneStatus` is `.refused` (not when it is `.checking` or `.ready`): the human may create and lock the `voice` profile after the app launched, and without this the status would stay `.refused`, `hermesLaneReady` would stay false, the router would never produce `.remote` and the per-submit preflight would never get a chance to fix it.       /// One round of the main queue, awaited. NOT the synchronous `drainMainQueue()` (that one uses `wait(for:)`, which real
  ```swift
      /// XCTest warns about or hangs on when it runs inside an `async` main-actor test; the stub does not notice).
      @MainActor
      static func drainMainRound() async {
          await withCheckedContinuation { (continuation: CheckedContinuation<Void, Never>) in
              DispatchQueue.main.async { continuation.resume() }
          }
      }

      /// Spins until `condition()` holds: each round awaits one main-queue round and yields, so a chain of
      /// hops (recognizer stream, dispatch, `await executor.execute`, dispatch, audit task, `backend.submit`) completes without a sleep.
      /// `maxRounds` is a ceiling, not a delay; a condition that never holds fails the test. The `test` argument is kept for
      /// call-site symmetry and is unused.
      @MainActor
      static func settle(_ test: XCTestCase, until condition: @MainActor () -> Bool, maxRounds: Int = 500,
                         file: StaticString = #filePath, line: UInt = #line) async {
          for _ in 0..<maxRounds {
              if condition() { return }
              await drainMainRound()
              await Task.yield()
          }
          if !condition() { XCTFail("condition not met after \(maxRounds) rounds", file: file, line: line) }
      }
  }
  ```

`ACPTransport` (`ACPTransport.swift`): a `Sendable` protocol with exactly these members: `func start() throws`; `func send(line: Data) throws`; `var lines: AsyncStream<Data> { get }`; `func terminate()`; `var processID: Int32? { get }` (the child's pid, which is also its process-group id; `nil` for the scripted transports of the tests, so the guard falls back to `terminate()` alone for them); `var workingDirectory: URL { get }` (the session's `cwd`); and **`func setExitHandler(_ handler: @escaping @Sendable (_ uptime: TimeInterval) -> Void)`**.

- **Exit handler.** The guard sets it BEFORE `start()` (B.6). `ProcessACPTransport` calls it exactly once, from its termination handler on its own serial queue with no lock held, AFTER it has finished the `lines` stream, passing the seconds the child lived; it also fires after a deliberate `terminate()` (the guard ignores that one by generation). `HermesFakeTransport` gets `simulateExit(uptime:)`, which finishes `lines` and calls the handler once.
- **`start()` fails fast when terminated.** `start()` throws if `terminate()` already ran (before or during `start()`). `ProcessACPTransport` has its own lock over `process` and `terminated` and never holds it across `run()` or a kill wait: `start()` = lock, throw if terminated, build the `Process`, unlock; `run()`; lock; if `terminated` flipped meanwhile, SIGKILL the group at once and throw, else store the process; unlock. `terminate()` = lock, set `terminated`, take the process, unlock, then close the pipes and signal it. `HermesFakeTransport.start()` calls its `onStart` hook WITHOUT holding the fake's lock, then re-checks `terminated` and throws if the hook terminated it (this is what makes the stop-during-spawn tests meaningful and deadlock-free).
- **Framing.** `send(line:)` receives the JSON WITHOUT a trailing newline; the transport appends exactly one `\n`. `ACPClient` serializes with `JSONSerialization` option `.sortedKeys`, but key order is still not a contract: tests compare PARSED dictionaries, never raw strings.
- **SIGPIPE-safe write (a crash rule: read twice).** Writing to the stdin pipe of a child that has exited raises SIGPIPE and kills desnotch (reproduced: a Swift program that imports AppKit and writes to the stdin pipe of an exited child dies with exit status 141). The spec's own scenarios (the child dies mid-turn, stop during spawn, handshake timeout) all write to a dying child. So: after creating the stdin `Pipe`, call `fcntl(fd, F_SETNOSIGPIPE, 1)` on the WRITE end (`pipe.fileHandleForWriting.fileDescriptor`) before anything is written. `send(line:)` writes with a `Darwin.write` loop (retry on `EINTR`; on `EAGAIN` `poll` the descriptor for writability, bounded by a few seconds; handle partial writes by advancing the offset until the whole line plus its `\n` is written) and THROWS on any other error, for example `EPIPE` (`write` returns -1 with `errno == EPIPE` once the flag is set, and the process survives). **Never use `FileHandle.write(_:)`** (it raises an Objective-C exception on a broken pipe) and never a bare `write(2)` without the flag. `send` also throws after `terminate()` has run (check the `terminated` flag under the transport's lock before writing; do not hold the lock across the write). `SubprocessBox.write` in `Support/SubprocessRunner.swift` is the in-repo precedent for the write loop, but it does NOT set `F_SETNOSIGPIPE`, so do not copy it blindly and do not edit it. **No deinit anywhere kills a child:** `ProcessACPTransport` and `HermesProcessGuard` have NO `deinit` that signals or terminates the child process (a dropped guard in a test is a simulated crash and must leave the child running, B.6).
- **Working directory.** `ProcessACPTransport` creates `<workingDirectoryRoot>/desnotch-voice-<uuid>` (mode 0700) in `init` or `start()` (decide once, document it, and make `workingDirectory` stable from then on) and deletes it in `terminate()`/shutdown; `HermesAgentBackend` passes `FileManager.default.temporaryDirectory` as the root. `HermesFakeTransport` returns a fixed absolute URL (for example `/tmp/desnotch-voice-test`, nothing is created for it). `ACPClient.handshake()` sends exactly `transport.workingDirectory.path` as `session/new`'s `cwd`, so the client never invents a path (B.4, and the `cwd == transport.workingDirectory.path` assertion in B.9).

Newline-delimited JSON-RPC 2.0 (reuse `AdapterLineBuffer`). `ProcessACPTransport` spawns `/usr/bin/perl -MPOSIX=setsid -e 'setsid(); exec {$ARGV[0]} @ARGV; exit 127' <hermesPath> -p voice acp` (the same fixed launcher `SubprocessRunner` uses, so the child leads its own session and process group, `pgid == pid`), environment `SubprocessRunner.sanitizedEnvironment()` (keeps `HOME`), stdin/stdout pipes, stderr to `FileHandle.nullDevice`, working directory = the fresh empty temp directory above (the child's cwd), removed on shutdown. (`sanitizedEnvironment()` sets a PATH without `~/.local/bin`; that is fine because the executable path is absolute.) All pipe callbacks run on one serial queue and carry a generation (copy the `MediaRemoteBridge` pattern: stale callbacks from a dead process must not touch the new stream).
**Test injection.** The command is injectable: `struct ACPLaunch: Sendable { var perl: URL; var arguments: [String] }` with `static func hermes(path: URL) -> ACPLaunch` as the production value, and `ProcessACPTransport.init(launch: ACPLaunch, workingDirectoryRoot: URL)`; `HermesProcessGuard` takes a launch PROVIDER `@escaping @Sendable () -> ACPLaunch?` (evaluated at every spawn, B.6/B.7; a test passes `{ ACPLaunch.command("...") }`) and a `pidFileDirectory: URL` (production: `~/Library/Application Support/desnotch/voice`; tests: a UUID temp directory). The real-process tests (B.6) point it at `/bin/sh -c '...'` through the same perl launcher. `ACPLaunch` lives in `ACPTransport.swift`; it has a test-only convenience, `static func command(_ shellCommand: String) -> ACPLaunch` (declared in `HermesFixtures.swift` as an extension, NOT in the production file), which builds `ACPLaunch(perl: URL(fileURLWithPath: "/usr/bin/perl"), arguments: ["-MPOSIX=setsid", "-e", "setsid(); exec {$ARGV[0]} @ARGV; exit 127", "/bin/sh", "-c", shellCommand])`, so every real-process test gets the same own-session, own-process-group child as production.

### B.4 ACP client (`ACPClient`)

Lenient decoding (`JSONSerialization` into dictionaries; unknown fields ignored; a malformed line is dropped). It speaks only: `initialize` (declare NO client capabilities: no file system, no terminal; check the reported `protocolVersion` with `HermesPreflight.checkProtocol`), `session/new` (`cwd` = `transport.workingDirectory.path`, `mcpServers: []`), `session/prompt` (one text content block, the utterance), `session/cancel`, and answers `session/request_permission`. Notifications `session/update` carry the updates. Any other agent->client REQUEST is answered with JSON-RPC error `-32601` (method not found). Request ids are monotonically increasing integers; responses are matched by id; **the `id` of an agent-to-client request such as `session/request_permission` may be an integer OR a string: store it as the raw JSON value and echo it back verbatim in the reply (never coerce it to `Int`)**; a timeout of 20 s on `initialize`/`session/new` and none on the streaming `prompt`. The wire keys are camelCase. The literal requests we send (the implementer re-checks them against `acp/schema.py`; if one differs, the schema wins and the report says so):

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1,"clientCapabilities":{}}}
{"jsonrpc":"2.0","id":2,"method":"session/new","params":{"cwd":"/private/var/.../desnotch-voice-<uuid>","mcpServers":[]}}
{"jsonrpc":"2.0","id":3,"method":"session/prompt","params":{"sessionId":"s1","prompt":[{"type":"text","text":"<utterance>"}]}}
{"jsonrpc":"2.0","method":"session/cancel","params":{"sessionId":"s1"}}
```

`session/cancel` is a NOTIFICATION (no `id`, no response). Fields we read from results: `initialize` -> `result.protocolVersion` (an integer); `session/new` -> `result.sessionId` (a string); `session/prompt` -> `result.stopReason` (B.5). Everything else in a result is ignored.

Map ACP updates to `AgentEvent`:

- **Message chunks** (`agent_message_chunk` text) -> accumulate; emit `.partial(accumulatedSoFar)` (bounded to 400 characters, keep the END of the text) at most every 100 ms (coalesce on the injected time).
- **Tool start.** Hermes sends ONE `tool_call` update (ToolCallStart) when a tool starts running, with NO `status` field (it defaults to pending) and NO separate tool-name field, and it never sends an `in_progress` update at the start. So a rule keyed on `in_progress` would emit nothing and every tool would run unnoticed (fail open). The rule is: emit `.toolActivity(kind:)` **exactly once per `toolCallId`**, on the FIRST sighting of that id in a `tool_call` OR a `tool_call_update`, **regardless of `status`** (absent, pending, in_progress, and also completed/failed for an id never seen before). - **Tool kind.** The name exists only as the title prefix (`build_tool_title` = `"<tool_name>: <preview>"`, or the bare name). `kind` = the title text before the first `:` (or the whole title when there is none), trimmed and lowercased; it must match `^[a-z0-9_.-]{1,40}$`, otherwise `kind = "unknown_tool"` (`ToolTierTable` maps it to T3, so it trips the wire). - **Permission ids are not tool starts.** A `toolCallId` that appeared in `session/request_permission` params (`toolCall.toolCallId`, `perm-check-N`) is registered as a permission id and NEVER emits `.toolActivity`: after the answer Hermes sends a `tool_call_update` for that id (`completed`/`failed`, `permissions.py` `await_permission`), which would otherwise look like an unseen tool and trip the wire on every approved command.

With the empty toolset this is intended: any tool that classifies T2 or higher trips R83 before a card can appear (`approvedToolStarts` is still 0), and a card-approved `terminal` is T3, so card-approved shell commands always end in a tripwire pause. This fails closed; do not "fix" the reducer. The coordinator's S3/S4 scenario tests therefore use T0/T1 tool names (`clock`) for approval flows.

Emit `.approvalNeeded(card)`.
- `respond(nonce:allow:)`: allow => reply `{"outcome":{"outcome":"selected","optionId":"allow_once"}}` ONLY; deny => `optionId` `deny` ONLY. If the nonce is unknown reply nothing. If the request offered no `allow_once`, deny; if it offered no `deny` either, reply `{"outcome":{"outcome":"cancelled"}}`. ### B.6 Process supervision (`HermesProcessGuard`) and hard stop

Shape (the type names, `HermesGuardError`, the `*` seams, the static helpers and the pid-file format are exact; everything else is yours):

```swift

enum HermesGuardError: Error, Equatable { case backoff, spawnFailed }

    static func isHermesACP(commandLine: String) -> Bool

    static func processStartSeconds(pid: Int32) -> Int?      // proc_pidinfo(pid, PROC_PIDTBSDINFO).pbi_start_tvsec, nil on any error

```

- **Lock discipline (exact; this is what keeps the stop path from deadlocking).** The guard's one `NSLock` protects only its small state (`current: (transport, generation)?`, the backoff struct, `retryNotBefore`). It is NEVER held while calling `transportFactory`, `transport.start()`, `send`, `terminate()`, `ps`, `killpg`, any wait or poll, or file IO: take the lock, flip or copy state, release it, then act. So `terminateNow()`, `hardStop(sendCancel:)`, `terminate(_:)` and `shutdown()` never wait on a spawn in progress and may be called from inside `transport.start()` on the same thread (the test hooks do exactly that). A mutex that is held across `start()` would deadlock `testStopDuringSpawnNeverSendsPrompt`; do not write one.
- **`ensureRunning()` (exact steps).** (1) Under the lock: if a current transport exists, return it; if `now() < retryNotBefore` throw `.backoff` (it spawns nothing and never sleeps). (2) Outside the lock: crash recovery of a stale pid file (below). (3) outside the lock `guard let resolved = launch() else { throw HermesGuardError.spawnFailed }` (the provider is evaluated here, at every spawn, never cached at init: a `hermes` installed after the app started is picked up by the next spawn, and a provider that returns nil spawns nothing, registers nothing and sets no backoff), then `let transport = transportFactory(resolved, workingDirectoryRoot)`; take a fresh generation `g`; `transport.setExitHandler { [weak self] uptime in self?.transportExited(generation: g, uptime: uptime) }`; then under the lock REGISTER `(transport, g)` as current. All of this happens BEFORE `start()`. (4) Outside the lock: `try transport.start()`; if it throws, under the lock drop the registration if it is still `g`, and throw `.spawnFailed`. (5) Under the lock check that `(transport, g)` is still current; if not (a `terminateNow`, `hardStop`, `shutdown` or `terminate(_:)` ran during `start()`), call `transport.terminate()` and throw `.spawnFailed`; otherwise write the pid file (below) and return the transport. Consequence: a stop that arrives while `start()` is running sees the half-started transport, terminates it, and `start()` fails fast (B.2); the backend's epoch check (B.7) then reports `stop_cancelled`.
- **Exit handling (`transportExited(generation:uptime:)`).** Under the lock: if `generation` is not the current one, ignore it (a deliberate stop already cleared `current` first, so a deliberate stop never counts as a crash and never sets a backoff); otherwise clear `current`, call `backoff.nextDelay(afterUptime: uptime)` and store `retryNotBefore = now() + delay`; then, outside the lock, delete the pid file ONLY IF the pid it records equals THIS transport's pid (read the file, parse it, compare, then delete; use the same compare-and-delete helper for every deletion the guard makes for its own child, deliberate stops included). Why: a dropped guard A (a test's simulated crash, or any late exit callback) can report its child's exit AFTER guard B has killed A's child and written B's own pid file; an unconditional delete would then remove B's file. The only unconditional deletions are crash recovery's own (an unparseable or unrelated file, below). Every deliberate termination (`terminateNow`, `hardStop`, `terminate(_:)`, `shutdown`) clears `current` under the lock BEFORE it signals anything. **The guard does not produce `process_exited`**: that failure belongs to the backend's reader loop (B.7).
- **Restart backoff.** Reuse `AdapterRestartBackoff` (`MediaRemote/MediaRemoteBridge.swift:366`: `mutating func nextDelay(afterUptime: TimeInterval?) -> TimeInterval`, first delay 1 s, doubling, capped at 30 s, and `mutating func recordHealthyOutput() -> Bool`). A child that exits on its own (mid-turn or before the handshake finished) reaches `transportExited` with the seconds it lived; a `submit`/`ensureRunning` that arrives while `now() < retryNotBefore` FAILS FAST with `.backoff` (mapped to `.failed(.agentFailed("backoff"))`) and spawns nothing; `markHealthy()` (after a successful handshake) calls `recordHealthyOutput()`. A process that dies mid-turn yields `.failed(.agentFailed("process_exited"))` (B.7).
- **Pid file (exact).** `hermes-acp.pid` inside `pidFileDirectory` (the directory is created with `FileManager.default.createDirectory(at:withIntermediateDirectories: true, attributes: [.posixPermissions: 0o700])`, because the audit logger only creates `~/Library/Application Support/desnotch/voice` once voice has run once; the file is mode 0600). Content EXACTLY `<pid> <start-seconds>\n`: two decimal integers separated by one space and a newline. `<start-seconds>` is the child's REAL start time read from the OS right after the spawn with `processStartSeconds(pid:)`, NOT the injected `now` (a test clock would never match the OS). If the start time cannot be read, write NO pid file (crash recovery then cannot kill that child, which fails safe). The file is deleted on every deliberate stop and on exit. `parsePidFile` returns nil unless the text is exactly two decimal integers separated by one space with an optional trailing newline and `pid > 1`.
- **Crash recovery kills only a process desnotch itself spawned (exact; PLAN section 14 item 10).** The pid file survives crashes and reboots, pids get reused, and Des runs other Hermes ACP sessions (the default profile, editor clients) whose command lines contain `hermes` and `acp`. A bare `hermes`-and-`acp` match is therefore NOT enough. On `ensureRunning`, read the pid file; absent or unparseable: delete it, kill nothing. Otherwise kill THAT process group only if ALL three hold: (a) `/bin/ps -p <pid> -o command=` output satisfies `isHermesACP(commandLine:)`, i.e. contains the exact consecutive tokens `-p voice acp` (which is what `ACPLaunch.hermes` always spawns); (b) `startTimesAgree(recorded: <file>, actual: processStartSeconds(pid))` (`abs(recorded - actual) <= 5`); (c) `getpgid(pid) == pid` (our child leads its own group). On ANY failure of any check, or any error (ps launch failure, timeout, non-zero exit, undecodable output, pid not alive, start time unreadable): delete the pid file and kill nothing. Never scan for other hermes processes. The kill is the `terminateNow()` tail (SIGTERM to the group, poll the same `alive(pid)` helper every 10 ms for up to 0.5 s, SIGKILL). **How to read the command line (synchronous, bounded).** `SubprocessRunner.run` is `async`, but `ensureRunning() throws -> ACPTransport` is synchronous, so do NOT use `SubprocessRunner` and do NOT make `ensureRunning` async. Run `/bin/ps -p <pid> -o command=` synchronously with `Process` and a `Pipe` (precedent for running `/bin/ps`: `ProcessMonitor/ProcessSampler.swift:45`, which uses the async runner; here it must be a synchronous `Process`), read at most 4 KB of its output, and wait at most 2 s (`terminate()` the `ps` if it is still running at the deadline).
- **`isHermesACP(commandLine:)`** (pure): split on whitespace (spaces, tabs, newlines), true iff three CONSECUTIVE tokens are exactly `-p`, `voice`, `acp` (case-sensitive; `-p voiceX acp`, `-p default acp`, a bare `hermes acp` and the empty string are all false). **Do not tighten it to look for the word `hermes`**: the installed launcher `~/.local/bin/hermes` is a `/bin/sh` wrapper that execs another `/bin/sh`, which execs `python3 -I -c '<inline script>' "$@"`; the pid is preserved and the running command line is the inline script followed by `-p voice acp`, so `hermes` appears only inside the script text and the three trailing tokens are the reliable part. `startTimesAgree` is `abs(recorded - actual) <= 5`.

- **`terminateNow()` (synchronous, on `HermesProcessGuard` and re-exported by `HermesAgentBackend`).** No `Task`, no `await`, callable from any thread (including from inside `transport.start()`), idempotent, returns only when finished: under the lock snapshot `(transport, pid)` and clear `current` in the same critical section; then, outside the lock, `killpg(pgid, SIGTERM)`, poll the SAME `alive(pid)` helper that `hardStop` uses (`kill(pid, 0) == 0` AND not a zombie) every 10 ms for at most 0.5 s, `killpg(pgid, SIGKILL)` only if the leader is still alive after that, call `transport.terminate()`, remove the pid file. A transport with `processID == nil` is only `terminate()`d. (The direct child is a zombie of desnotch's own `Process` until it is reaped, and a zombie still answers `kill(pid, 0)`: a bare `kill(pid, 0)` loop would always wait the full 0.5 s on the main thread at quit.) `VoiceCoordinator.stop()` reaches it through `terminateAgentNow`, and `AppComposition.stopOwnedResources()` may call it too; this is what prevents an orphaned `hermes acp` at quit.
- **Never signal a group the guard no longer owns.** Send `killpg` only for a snapshot taken while the transport had NOT yet reported its exit (the termination handler runs after the child is reaped, and after that the pid could in theory be reused by an unrelated process). If the exit was already reported when the snapshot was taken, send no signal at all and let `hardStop` only report survivors. Also never signal when `processID` is nil.
- `hardStop(sendCancel:)` (this is what `emergencyStop()` runs): (1) snapshot all descendant pids of the child (`proc_listchildpids`, recursively: **`proc_listchildpids(ppid, buffer, buffersize)` returns the NUMBER of pids written, NOT a byte count** (unlike `proc_listpids`; measured: two `sleep` children give a return of 2, and the usual bytes-divided-by-`MemoryLayout<Int32>.size` computation gives 0 and an EMPTY snapshot, which would make `survivors` always `[]`); use `buf.prefix(Int(n))`, ignore a return `<= 0`, size the buffer generously (for example 256 pids, retrying larger when the return fills it), recurse breadth-first with a visited set and a depth cap of 64 levels or 512 pids total) and the `(transport, pid)` as above (clearing `current`), (2) call `sendCancel()` (the backend sends `session/cancel`), (3) wait `VoiceTiming.hardStopGrace` (0.5 s), (4) `killpg(pgid, SIGTERM)`, (5) wait 0.5 s, (6) `killpg(pgid, SIGKILL)`, (7) poll every 10 ms for up to 0.5 s until no snapshot pid is a survivor, (8) `survivors` = names (via `proc_name`) of snapshot pids that are still alive. **A pid is alive only if `kill(pid, 0) == 0` AND it is not a zombie** (`proc_pidinfo(pid, PROC_PIDTBSDINFO, ...)`, `pbi_status != SZOMB`): a killed but not yet reaped process still answers `kill(pid, 0)`, which would make the report flaky. Then call `transport.terminate()` and drop it (the next submit respawns). A transport whose `processID` is `nil` (a test transport) is only `terminate()`d.

### B.7 `HermesAgentBackend: AgentBackend`

Wraps locator + preflight + guard + client. It is the single instance `AppComposition` holds (A.1). Fixed seams (type and parameter names are exact because the tests need them; helpers are yours):

```swift
final class HermesAgentBackend: AgentBackend, @unchecked Sendable {          // ALL mutable state behind one NSLock (sync helpers only), plus the separate HermesEpoch below
    let id = "hermes"
    init(locator: HermesLocator = HermesLocator(), configReader: ConfigReading = VoiceProfileConfigReader(),
         fileFlags: FileFlagReading = VoiceProfileFlagReader(), launch: ACPLaunch? = nil,   // nil = RESOLVE AT EVERY SPAWN: locator.hermesURL().map(ACPLaunch.hermes(path:)); a non-nil (test) launch is used as-is
         pidFileDirectory: URL = FileAuditLogger.defaultDirectory(),
         transportFactory: @escaping @Sendable (ACPLaunch, URL) -> ACPTransport = { ProcessACPTransport(launch: $0, workingDirectoryRoot: $1) },
         scheduler: HermesScheduling = DispatchHermesScheduler(), now: @escaping @Sendable () -> Date = { Date() })
    func terminateNow()            // synchronous; re-exports the guard's
}
```

The backend builds its guard ONCE in `init` as `HermesProcessGuard(launch: provider, pidFileDirectory:workingDirectoryRoot: FileManager.default.temporaryDirectory, transportFactory:now:)` from its own init parameters (the `killGroup` seam keeps its default), where `provider` is `{ launch ?? locator.hermesURL().map { ACPLaunch.hermes(path: $0) } }` (it captures the `launch` parameter and the `locator` value, which is `Sendable`; `hermesURL()` is re-evaluated at each spawn). `hermesURL()` returns an Optional and the preflight (P1) is re-run on every submit, so a `hermes` installed after the app started passes P1 on the next submit AND is then spawned from its real path (never from a stale or placeholder one); if `hermesURL()` is still nil at spawn time, the guard maps it to `.spawnFailed`. `preflight()` runs B.3 (and the live check P8 when connected). The `ACPClient` (suggested: `init(transport:mapper:now:newNonce:scheduler:onLateEvent:)`, where `scheduler: HermesScheduling` drives the 20 s handshake timeout so a test fires it by hand, and `onLateEvent` is the late-activity closure below; `func handshake() async throws -> String` returning the session id; `func prompt(_:) -> AsyncStream<AgentEvent>`; `func respond(nonce:allow:)`; `func cancel()`) and `HermesEventMapper` (a value type with `mutating func ingest(...)` taking `at: Date`) are internal to Part B; their tests drive them with a scripted `ACPTransport`.

**Turn epoch (the stop and cancel guarantees; read twice).** `submit` is a synchronous function that returns the stream; it takes its epoch snapshot BEFORE it returns (the coordinator calls it synchronously, A.3) and does the asynchronous work (preflight, spawn, handshake, prompt) in its own task. The epoch is an integer in a tiny separate class, `final class HermesEpoch: @unchecked Sendable` (in `HermesAgentBackend.swift`: ONE `NSLock` around ONE `Int`; `func bump()` and `var value: Int`; it calls nothing while holding the lock), so the stop path never needs the backend's main state lock. `cancelTurn()`, `emergencyStop()`, `shutdown()` and `terminateNow()` each call `epoch.bump()` as their FIRST action. `submit` takes `myEpoch = epoch.value` when it is called and RE-CHECKS `epoch.value == myEpoch` (a) after the preflight returns, (b) after `ensureRunning()` returns OR throws, (c) after `session/new` returns, and (d) immediately before `session/prompt` is sent. On a mismatch it aborts: it sends NO `session/prompt`, it terminates the transport it obtained in this very call with `guard.terminate(transport)` (which kills the guard's current child if that is the one, and otherwise only that transport, so a stale submit can never kill the child of a newer turn), and it finishes the stream with `.failed(.agentFailed("stop_cancelled"))`. The epoch check wins over any error: an `ensureRunning()` that threw because a stop arrived during `start()` reports `stop_cancelled`, not `spawn_failed`.

**Locks and the stop path (exact; there is no spawn lock).** Do not spawn under a backend lock: that deadlocks any test or stop that reaches `terminateNow()` from inside `transport.start()` (the lock is not re-entrant). The rules: (1) `HermesEpoch` and `HermesProcessGuard` each have their own lock and are LEAVES: nothing is called while holding either; (2) the backend's own lock guards its remaining state (`killPending`, the in-flight turn record, the client, the session id, the scheduled-task handles) and is accessed only through small synchronous helpers; it is NEVER held across an `await`, `ensureRunning()`, `transport.start()`, `send`, `terminate`, `killpg`, a scheduler call or any callout (take the lock, copy or flip state, release, then act); (3) the guard registers the new transport BEFORE it calls `start()` and drops its lock around it (B.6), so a stop that runs during the spawn either sees the registered transport and terminates it (and `start()` then fails fast) or ran before the registration, in which case check (b) sees the bumped epoch and the submit itself terminates what it spawned. Together with (a) to (d) this is why a STOP during `thinking` (when the backend may still be preflighting, spawning or about to send the prompt) can never be followed by a prompt from the unobserved agent.

`submit(utterance)` (called by the coordinator for `.submitToAgent`):
0. **No slash commands.** Hermes treats any prompt whose text starts with `/` as a slash command (`acp_adapter/server.py:833-834`: `/model`, `/compress`, ...). If the first non-whitespace character of `utterance` is `/` (a spoken transcript will not normally start with one, but the typed debug path can), finish with `[.failed(.agentFailed("slash_prefix"))]` and touch nothing (no preflight, no spawn, no `.status("started")`, so the daily counter is not charged). Strip nothing: refusing is the safe choice.
1. If a prompt is already in flight (an active turn that is neither cancelled nor terminal): finish with `[.failed(.agentFailed("busy"))]` and touch nothing.
2. If `killPending` is set (a cancelled turn's process may still be alive, see `cancelTurn`): complete the kill NOW (group SIGTERM, up to 0.5 s, SIGKILL, drop the transport, clear the flag) BEFORE anything else, so a new utterance is never submitted into a possibly still-running session.
3. Re-run preflight; refused => stream `[.failed(.preflightRefused(reason))]` (the coordinator maps that to `model.setHermesLaneStatus(.refused(reason))` and an audit record, A.3). Epoch check (a).
4. Ensure the process is running: `guard.ensureRunning()` (it throws only `HermesGuardError`: `.backoff` becomes `.failed(.agentFailed("backoff"))`, `.spawnFailed` and any other error become `.failed(.agentFailed("spawn_failed"))`), then `initialize` and `session/new` once per process (reuse the session for the idle window). Epoch checks (b) and (c). Failure mapping of the handshake (all of them also terminate the transport with `guard.terminate(transport)`, so a half-working child is never kept): a 20 s timeout (`new_session` builds the agent in a thread and can be slow on a cold start) is `.failed(.agentFailed("handshake_timeout"))`; the lines stream ending before the answer is `.failed(.agentFailed("process_exited"))`; a protocol version outside `HermesACP.supportedProtocolVersions` (`HermesPreflight.checkProtocol`) is `.failed(.preflightRefused(.protocolMismatch))` (the coordinator then sets the lane status to `.refused(.protocolMismatch)`, A.3). A successful handshake calls `guard.markHealthy()`.
5. Epoch check (d), then send `session/prompt`, then emit `.status("started")` (the coordinator increments `dailyTurns` when it sees it).
6. Forward the mapped events; the stream ends after `.finished`/`.failed`. **`process_exited` is owned HERE, by the backend's reader loop** (not by the guard, not by the client): `ACPClient.prompt(_:)` finishes its stream WITHOUT a terminal event only when the transport's `lines` ended; the loop that iterates it, on seeing the stream end with no `.finished`/`.failed`, emits `.failed(.agentFailed("process_exited"))` if `epoch.value == myEpoch`, or `.failed(.agentFailed("stop_cancelled"))` if the epoch moved.

`cancelTurn()` (the reducer's soft cancel: Esc, spoken "stop", the 180 s budget R89, the 12-step budget R82): bump the epoch; **first answer every still-unanswered permission request of the turn with `deny`** (the reducer's spoken-cancel rule R103 emits `.cancelAgentTurn` while a card may be on screen, without a `.respondToApproval`, so the backend must not leave the agent's request open); then, if a turn is in flight, send `session/cancel`, set `killPending = true`, and schedule through the injected `scheduler` a hard kill after `VoiceTiming.hardStopGrace`; if the prompt response arrives before that, cancel the scheduled task and clear `killPending`. When the task fires it does the same process-group kill as `emergencyStop()` (no reducer change, no coordinator involvement) and drops the transport. Finish the turn's stream with `.failed(.agentFailed("stop_cancelled"))` only if no terminal event was sent (the reducer has already left the turn, so the event is ignored, but the consumer's loop ends). A soft cancel alone does nothing to an agent that ignores it; this escalation is what makes the 180 s and 12-step budgets real.

**Late activity after a cancel (the reader outlives the prompt stream).** `ACPClient`'s reader task lives as long as the transport's `lines` stream, NOT as long as one `prompt(_:)` stream: updates that arrive when no prompt stream is active (the turn finished, was cancelled or was superseded) are routed to a backend-supplied closure, `onLateEvent: @Sendable (ACPLateEvent) -> Void` (an `ACPClient.init` parameter), with `enum ACPLateEvent: Equatable { case toolActivity(kind: String), permissionRequest(nonce: String) }`. The backend's handler runs the rule: a late first-sighting `tool_call` (`.toolActivity`) triggers the hard kill IMMEDIATELY (`guard.terminate(transport)`; the reducer is no longer watching that turn, so nobody else would trip the wire); a late `.permissionRequest` is answered `deny` FIRST (`respond(nonce:, allow: false)`), then the kill. Updates for ids the mapper already knows (a later `completed` update of a tool that started during the turn) emit nothing and so never reach the handler. `emergencyStop()` runs the guard's `hardStop(sendCancel:)` and returns its report.

## 5. Global rules

These apply to every work package. They are not suggestions.

1. **No new dependencies.** No Swift packages, no vendored code, no shell tools that are not already on a stock macOS 13+
   (and not already used by the repo). Apple system frameworks are fine (`Speech`, `AVFoundation`, `CryptoKit`, `Carbon.HIToolbox`, ...).
   Do not edit `Package.swift`.
2. **Swift 5.10 on CI (macos-14).** The compiler on CI is stricter about actor isolation than the Swift 6.1 on this machine.
   - Mark every SwiftUI `View` struct and every type that touches a `@MainActor` type (`SettingsStore`, controllers,
     `NSWorkspace` UI calls, `VoiceSessionModel`) explicitly `@MainActor`. Never rely on inferred isolation.
   - Escaping closures that capture a class instance use `[weak self]`.
   - `AsyncStream`/`Task` bodies that touch `@MainActor` state are `Task { @MainActor [weak self] in ... }`.
   - Protocols and value types that cross isolation are `Sendable`. A class that is `@unchecked Sendable` guards ALL its mutable
     state with one `NSLock` (or one serial `DispatchQueue`) and says so in a doc comment.
   - Do not use: `Mutex`/`Synchronization`, `sending`, `consuming`/`borrowing`, typed throws (`throws(X)`), Swift Testing
     (`import Testing`, `#expect`), macros, `nonisolated(unsafe)` (outside tests it hides bugs), `@preconcurrency` imports as a
     way to silence a warning, or any API newer than macOS 13.
   - Do not put `await` inside an `XCTAssert...(...)` argument; assign to a `let` first.
   - Never call `NSLock.lock()` / `unlock()` inside the body of an `async` function or closure: the Swift 6.1 compiler warns
     "unavailable from asynchronous contexts" (breaking rule 3). Put every locked access in a private SYNCHRONOUS helper
     (`private func appendLocked(...) -> Bool`) and call the helper from the async body. The frozen
     `Tests/DesnotchCoreTests/Voice/VoiceTestSupport.swift` (`ScriptedBackend.recordResponse`) shows the pattern.
3. **No warnings.** `swift build` must be warning-free for the whole package, and the harness build must show no warnings
   from your files. No `// swiftlint:disable`. No `try!` / `as!` / `!` force unwraps in non-test code unless the
   spec above shows one.
4. **No secrets, no real user data.** Never read, print, log or commit `auth.json`, `.env`, keychain items, `~/.ssh`,
   `~/.hermes/config.yaml`, vault or engagement files. Tests use synthetic fixtures only.
5. **Privacy boundary.** A transcript, a command line, a reply text or an audio buffer is live content. Voice code logs
   NOTHING: no `print`, no `NSLog`, no `os_log`, no `Logger` anywhere under `Sources/DesnotchCore/Voice` or in the voice UI files (the
   final-check `rg` bans all of them, in comments too: explain a ban with words, never with the literal token). Surface a failure as a typed `VoiceFailure` (its `code` is what the audit log stores).
   Never write live content to disk (the audit log stores hashes and codes only) and never pass it to VoiceOver announcements.
6. **No git.** Do not run `git add`, `git commit`, `git push`, `git merge`, `git rebase`, `git stash`, `git checkout` of other
   branches, `git worktree`, or `git reset`. Leave your changes uncommitted in your worktree; the orchestrator reviews and commits.
   Reading (`git status`, `git diff`, `git log`) is fine.
7. **Stay inside your file list.** Create/edit ONLY the paths in your "Files" section. Never edit
   `Sources/DesnotchCore/Voice/Contracts/*`, `Tests/DesnotchCoreTests/Voice/VoiceTestSupport.swift`,
   `Tests/DesnotchCoreTests/Voice/VoiceContractSmokeTests.swift`, `Package.swift`, `AGENTS.md`, `CLAUDE.md`, `CHANGELOG.md`,
   `docs/voice/*`, `scripts/voice-harness/*`, `.github/*`, or anything under `Sources/DesnotchCore/MediaRemote/Vendor/` **except that
   Part C (and only Part C) edits `AGENTS.md`, `CHANGELOG.md` and `README.md`** (`CLAUDE.md` is a symlink to `AGENTS.md`: never write
   it separately).
   If you believe a contract file is wrong or incomplete, do NOT edit it: implement the literal spec, work around it locally
   in your own files, and add an `AMENDMENT REQUEST:` paragraph to your final report.
8. **Tests are XCTest, deterministic, and fast.** No sleeps (`Thread.sleep`, `Task.sleep`) to wait for results: use the
   helpers in `Tests/DesnotchCoreTests/TestSupport.swift` (`drainMainQueue`, `drainMainOperationQueue`) or await a stream. No
   network, no microphone, no real `~/Library` paths (use `FileManager.default.temporaryDirectory` + a UUID folder and delete
   it in `tearDown`), no real `UserDefaults.standard` (use `UserDefaults(suiteName:)` and remove the domain in `tearDown`).
   Tests must compile under real XCTest on Xcode 15: only use the assertion functions the existing tests use
   (`XCTAssertEqual/True/False/Nil/NotNil/NotEqual/Greater...`, `XCTUnwrap`, `XCTAssertThrowsError`, `XCTFail`,
   `expectation`/`wait(for:)`). All test files of all packages share ONE test module: test doubles and helper types you write are
   `private`/`fileprivate` unless another test file of YOUR package must reuse them (then they are internal and use the name or
   prefix your package doc prescribes). **File-scope (column 0) helper FUNCTIONS and constants are `private` too** (`private func step(...)`, `private let t0`): an internal helper with the same signature as a `private` one in another file of the module is an "invalid redeclaration" error, while two `private` ones coexist (WP-LOGIC's `env`, `ctx`, `step`, `run`, `t0` are `private` for that reason), and before naming any type run `rg -n "class <Name>|struct <Name>" Tests` and change the name
   on a collision. `Tests/DesnotchCoreTests/Voice/VoiceTestSupport.swift` (frozen) already provides `FakeVoiceClock`,
   `ScriptedRecognizer`, `RecordingExecutor`, `ScriptedBackend` and `InMemoryFileWriter`; use them as they are. A test class that
   touches a `@MainActor` type (`SystemLocalExecutor`, `VolumeDucker`, `CarbonPushToTalk`, `VoiceCuePlayer`, `NSHostingView`,
   `VoiceSessionModel`, `SettingsStore`, or a double that conforms to a `@MainActor` protocol) is declared
   `@MainActor final class XTests: XCTestCase {` (the harness accepts the attribute on the same line or on the line before).
   Doubles that conform to a `@MainActor` protocol are themselves `@MainActor` and can only be created from `@MainActor` code.
9. **Style.** Match the surrounding code. No trailing whitespace, exactly one final newline, never two blank lines in a
   row (CI's SwiftLint fails the build on these; run `scripts/voice-harness/lint-lite.sh`). Doc comments explain WHY.
   Names in this plan are exact: do not rename a type, method, case or file that the plan names.
10. **Do not "improve" the spec.** If a table says X, the code does X, even if you can think of a better X. If the spec is
    silent or contradicts itself, choose the SAFER behavior (refuse / fail closed), say so in your final report under

11. **Final report.** End your work with a message that lists: every file you created/changed (full paths), the exact
    commands you ran and their last lines (build, harness, lint), the number of tests you added, anything you could not do and
    why, `QUESTIONS`, and any `AMENDMENT REQUEST`. Do not claim a command passed unless you ran it and read its output.
